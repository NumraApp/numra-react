# Security policy

`@getnumra/react` runs in the page and holds no credential — but what it renders
is what a merchant acts on before releasing a parcel, so please treat a
weakness in it accordingly.

## Supported versions

| Version | Supported |
|---|---|
| 1.0.x | Yes |

1.0.0 is the first public release, so there is nothing older to support. When
a later major line opens, this table will say how long 1.x keeps receiving
security fixes.

## Reporting a vulnerability

Mail **security@numra.ma**. Put the package name in the subject.

**Do not open a public issue, pull request or discussion for a security
problem.** A public report is a working exploit for every merchant running the
released version until a fix ships, and the fix takes longer than the reading.

Useful to include:

- the package version and the React version;
- what an attacker can do, and what they need in order to do it;
- the smallest reproduction you can manage.

Please do not send a live API key, a webhook secret, or a real customer's
phone number. A rotated test key and an invented number make the same point.

## What to expect

- An acknowledgement within three working days.
- An assessment, and either a fix or an explanation of why we do not consider
  it one, within ten working days.
- A fixed release, an entry in [CHANGELOG.md](CHANGELOG.md), and a published
  advisory once merchants have had a chance to upgrade.
- Credit under whatever name you want, or none.

We will ask you to hold public disclosure until the fixed release is out. We
will not ask you to hold it indefinitely.

## In scope

Any route by which this package could accept a credential or reach the Numra
API directly rather than the merchant's own endpoint — the whole reason it
exists is that a key in a bundle is a key in everyone's hands.

Also in scope: anything that makes the rendered verdict disagree with the check
it was handed — a blacklisted number shown as anything milder, or an unrated
number shown as low risk — injection through a check's fields into the badge
markup, and a superseded or aborted lookup whose answer still lands.

## Out of scope

Findings that require a merchant to have already published their own API key,
weaknesses in the merchant's own endpoint rather than in this package, and
reports generated by a scanner without a reproduction.

Behaviour that belongs to `@getnumra/browser` should still be reported here if you
found it here; we will route it. Do not open a public issue in either
repository.
